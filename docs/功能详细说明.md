# AI-EdgeHub 功能详细说明文档

## 1. 系统概述

AI-EdgeHub 是一个边缘智能中台系统，旨在为传统安防设备和工业场景提供AI视觉能力。系统采用前后端分离架构，支持多种视频流接入、AI模型推理、规则引擎配置和工业联动输出。

## 2. 核心功能模块

### 2.1 仪表盘（Dashboard）

#### 功能描述
系统运行状态的可视化监控中心，实时展示系统性能指标、通道状态和告警信息。

#### 功能特性
- **系统性能监控**
  - CPU使用率实时显示
  - 内存使用率实时显示
  - 性能数据历史趋势（待实现）

- **通道状态统计**
  - 总通道数/活跃通道数
  - 每个通道的实时FPS
  - 每个通道的推理延迟
  - 通道在线/离线状态

- **任务运行状态**
  - 总任务数/运行中任务数
  - 任务执行状态监控

- **最近告警记录**
  - 显示最近5条告警信息
  - 告警类型、内容、置信度
  - 告警时间戳
  - 告警图片（如有）

#### 技术实现
- 前端每5秒自动刷新数据
- 后端通过psutil获取系统性能指标
- Redis存储实时通道状态和性能数据
- WebSocket推送实时更新（待实现）

### 2.2 通道管理（Channel Management）

#### 功能描述
管理视频流接入通道，支持多种协议的视频源配置和管理。

#### 功能特性
- **通道列表管理**
  - 显示所有已配置的通道
  - 通道基本信息（名称、协议、地址、状态）
  - 通道操作（预览、编辑、删除）

- **新增通道**
  - 支持协议类型：
    - RTSP（实时流协议）
    - RTMP（实时消息协议）
    - ONVIF（网络视频标准）
    - USB（USB摄像头）
    - FILE（本地视频文件）
  - 通道名称和描述配置
  - 视频流地址输入

- **视频流预览**
  - 新增通道时实时预览
  - 验证视频流地址有效性
  - 预览成功后才能保存通道

- **批量检测**
  - 一键检测所有通道在线状态
  - 显示连接状态和错误信息
  - 掉线通道标记为红色

#### 技术实现
- 使用FFmpeg拉取视频流
- OpenCV进行视频帧提取
- 异步检测通道连接状态
- 视频流预览通过WebSocket转发（待实现）

### 2.3 模型中心（Model Hub）

#### 功能描述
AI模型文件的上传、管理和分析，支持多种模型格式。

#### 功能特性
- **模型列表**
  - 模型卡片展示
  - 显示模型名称、格式、创建时间
  - 显示模型输入尺寸和标签（需先分析）

- **上传模型**
  - 支持拖拽上传
  - 支持的文件格式：
    - ONNX (.onnx)
    - OpenVINO (.xml + .bin)
    - PaddlePaddle (.pdmodel)
  - 模型名称和描述配置
  - 自动识别模型格式

- **模型分析**
  - 自动提取模型输入尺寸
  - 自动提取模型标签列表
  - 显示模型输入形状
  - 更新模型元数据

- **模型删除**
  - 删除模型记录和文件
  - 确认对话框防止误删

#### 技术实现
- 文件上传使用multipart/form-data
- OpenVINO/ONNX Runtime加载模型分析
- 模型文件存储在uploads/models目录
- 模型元数据存储在SQLite数据库

### 2.4 任务配置（Task Configuration）

#### 功能描述
创建和配置AI推理任务，包括资源选择、ROI配置和规则设置。

#### 功能特性
- **任务列表**
  - 显示所有任务
  - 任务状态（运行中/已停止/已暂停）
  - 任务操作（编辑、启动、停止、克隆、删除）

- **三步向导创建任务**

  **Step 1: 选择资源**
  - 选择视频通道
  - 选择AI模型
  - 输入任务名称和描述

  **Step 2: 配置ROI（待实现）**
  - 视频画面实时预览
  - 绘制ROI区域：
    - 多边形区域
    - 矩形区域
    - 绊线（虚拟线）
  - ROI区域可视化（半透明蓝色蒙版）
  - 支持多个ROI区域

  **Step 3: 设置规则**
  - 目标标签选择（从模型标签中选择）
  - 置信度阈值设置（0-1滑块）
  - 连续帧数设置（连续N帧识别才触发）
  - 检测频率设置（每N帧检测一次）

- **输出配置（待实现）**
  - Modbus TCP输出配置
  - MQTT消息推送配置
  - Webhook HTTP请求配置
  - TCP Socket输出配置

- **任务控制**
  - 启动任务：开始AI推理
  - 停止任务：停止AI推理
  - 暂停任务：暂停推理（待实现）
  - 克隆任务：复制任务配置

- **调试模式（待实现）**
  - 实时显示AI识别框
  - 显示识别结果和置信度
  - 规则判定日志
  - 触发动作日志

#### 技术实现
- 任务配置存储在SQLite数据库
- 任务调度器管理任务生命周期
- 视频流处理使用多线程
- 推理引擎使用OpenVINO/ONNX Runtime
- 规则引擎执行ROI判定和逻辑规则

### 2.5 工业互联（Connectivity）

#### 功能描述
配置和管理工业联动接口，包括Modbus TCP、MQTT和Webhook。

#### 功能特性
- **Modbus TCP配置**
  - PLC IP地址和端口配置
  - 从站ID配置
  - 超时时间配置
  - 连接测试功能
  - 模拟触发功能（测试硬件联动）

- **MQTT配置**
  - MQTT Broker地址和端口
  - 用户名和密码认证
  - 主题前缀配置
  - 连接测试功能
  - 消息推送测试

- **Webhook配置**
  - Webhook URL配置
  - HTTP方法选择（GET/POST）
  - 自定义请求头（JSON格式）
  - 配置保存

- **模拟触发**
  - 选择输出类型
  - 手动触发测试
  - 验证硬件联动是否正常

#### 技术实现
- Modbus TCP使用pymodbus库
- MQTT使用paho-mqtt库
- Webhook使用aiohttp/httpx库
- 配置存储在数据库或配置文件
- 异步执行避免阻塞主线程

## 4. 数据流说明

### 4.1 视频流处理流程

```
视频源 (RTSP/RTMP/ONVIF/USB/FILE)
    ↓
FFmpeg 拉流
    ↓
帧缓冲区 (双端队列)
    ↓
图像预处理 (Resize, Normalize, BGR→RGB)
    ↓
推理引擎 (OpenVINO/ONNX Runtime)
    ↓
后处理 (NMS, ROI判定)
    ↓
规则引擎 (置信度过滤, 连续帧判定)
    ↓
触发动作 (Modbus/MQTT/Webhook)
    ↓
结果推送 (WebSocket → 前端显示)
```

### 4.2 任务执行流程

```
1. 用户创建任务配置
    ↓
2. 系统加载视频流
    ↓
3. 系统加载AI模型
    ↓
4. 启动推理线程
    ↓
5. 循环处理：
   a. 提取视频帧
   b. 执行AI推理
   c. 应用ROI过滤
   d. 执行规则判定
   e. 触发联动动作
   f. 推送结果到前端
```

## 5. API接口说明

### 5.1 通道管理API

- `GET /api/v1/channels` - 获取通道列表
- `POST /api/v1/channels` - 创建通道
- `GET /api/v1/channels/{id}` - 获取通道详情
- `PUT /api/v1/channels/{id}` - 更新通道
- `DELETE /api/v1/channels/{id}` - 删除通道
- `POST /api/v1/channels/preview` - 预览视频流
- `POST /api/v1/channels/batch-check` - 批量检测通道状态

### 5.2 模型管理API

- `GET /api/v1/models` - 获取模型列表
- `POST /api/v1/models` - 上传模型
- `GET /api/v1/models/{id}` - 获取模型详情
- `DELETE /api/v1/models/{id}` - 删除模型
- `POST /api/v1/models/{id}/analyze` - 分析模型元数据

### 5.3 任务管理API

- `GET /api/v1/tasks` - 获取任务列表
- `POST /api/v1/tasks` - 创建任务
- `GET /api/v1/tasks/{id}` - 获取任务详情
- `PUT /api/v1/tasks/{id}` - 更新任务
- `DELETE /api/v1/tasks/{id}` - 删除任务

- `GET /api/v1/dashboard/stats` - 获取系统统计

- `GET /api/v1/connectivity/config` - 获取互联配置

## 6. 数据库设计

### 6.1 表结构

**channels表** - 视频通道
- id, name, url, protocol, status, description, created_at, updated_at

**models表** - AI模型
- id, name, file_path, format, input_size, labels, description, created_at

**tasks表** - 任务配置
- id, name, channel_id, model_id, roi_config, rule_config, output_config, status, description, created_at, updated_at

**alerts表** - 告警记录
- id, task_id, alert_type, content, confidence, image_path, created_at

### 6.2 Redis数据结构

- `channel:{id}:status` - 通道状态
- `channel:{id}:fps` - 通道帧率
- `channel:{id}:latency` - 推理延迟
- `task:{id}:stats` - 任务统计信息
- `system:performance` - 系统性能指标
- `alert:recent` - 最近告警列表

## 9. 使用场景示例

### 9.1 轮胎红圈识别场景

1. **创建通道**
   - 添加RTSP摄像头通道
   - 预览视频流确认连接正常

2. **上传模型**
   - 上传训练好的红圈检测模型（ONNX格式）
   - 分析模型，确认标签：solid（实心）、hollow（空心）

3. **创建任务**
   - 选择摄像头通道和模型
   - 绘制ROI区域（轮胎检测区域）
   - 设置规则：
     - 目标标签：hollow
     - 置信度阈值：0.9
     - 连续帧数：2
   - 配置输出：Modbus TCP，寄存器地址0001，数值1

4. **启动任务**
   - 启动任务开始AI推理
   - 实时查看识别结果和告警日志
   - 验证PLC联动是否正常

### 9.2 安全帽检测场景

1. **批量创建通道**
   - 添加多个摄像头通道
   - 批量检测通道状态

2. **上传安全帽检测模型**
   - 上传ONNX模型
   - 分析模型标签：person、helmet、no_helmet

3. **批量创建任务**
   - 为每个摄像头创建任务
   - 使用克隆功能快速复制配置
   - 仅修改通道地址

4. **配置告警推送**
   - 设置MQTT推送
   - 配置Webhook通知
   - 测试告警推送

## 10. 注意事项

1. **性能要求**
   - 单次推理延迟需控制在100ms以内
   - 支持多路视频流并行处理
   - CPU负载监控和限流

2. **稳定性要求**
   - 支持7×24小时运行
   - 进程自愈机制（Watchdog）
   - 视频流断线自动重连

3. **易用性要求**
   - 全Web界面配置
   - 无需修改代码即可上线新场景
   - 提供详细的操作文档

4. **安全性要求**
   - API认证和授权
   - 敏感配置加密存储
   - 文件上传安全检查
