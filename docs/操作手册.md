## 1. 系统概述

### 1.1 系统简介

AI-EdgeHub 是一个边缘智能中台系统，为传统安防设备和工业场景提供AI视觉能力。系统支持多种视频流接入、AI模型推理、规则引擎配置和工业联动输出。

### 1.2 核心功能

- **视频流管理**：支持RTSP、RTMP、ONVIF、USB、本地文件等多种视频源
- **AI模型管理**：支持ONNX、OpenVINO、PaddlePaddle模型格式
- **任务配置**：可视化ROI绘制、规则引擎配置
- **工业联动**：支持Modbus TCP、MQTT、Webhook输出
- **实时监控**：系统性能监控、告警管理

### 1.3 系统要求

**后端要求**：
- Python 3.8+
- Windows/Linux
- 推荐配置：Intel i7-12700或更高，16GB内存

**前端要求**：
- Node.js 16+
- 现代浏览器（Chrome、Firefox、Edge）

## 2. 快速开始

### 2.1 后端安装

#### 2.1.1 环境准备

```bash
# 创建虚拟环境（推荐）
python -m venv venv

# Windows激活虚拟环境
venv\Scripts\activate

# Linux/Mac激活虚拟环境
source venv/bin/activate
```

#### 2.1.2 安装依赖

```bash
cd backend
pip install -r requirements.txt
```

#### 2.1.3 配置环境变量

复制 `.env.example` 为 `.env` 并修改配置：

```bash
cp .env.example .env
```

编辑 `.env` 文件：

```env
# 应用配置
APP_NAME=AI-EdgeHub
DEBUG=False

# 服务器配置
HOST=0.0.0.0
PORT=8000

# 数据库配置
DATABASE_URL=sqlite+aiosqlite:///./ai_edgehub.db

# Redis配置（可选）
REDIS_HOST=localhost
REDIS_PORT=6379

# CORS配置
CORS_ORIGINS=http://localhost:5173
```

#### 2.1.4 启动后端服务

```bash
# 方式1：使用启动脚本
python run.py

# 方式2：使用uvicorn
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

启动成功后，访问：
- API文档：http://localhost:8000/api/docs
- 健康检查：http://localhost:8000/health

### 2.2 前端安装

#### 2.2.1 安装依赖

```bash
cd frontend
npm install
```

#### 2.2.2 启动开发服务器

```bash
npm run dev
```

启动成功后，访问：http://localhost:5173

#### 2.2.3 生产构建

```bash
npm run build
```

构建产物在 `dist/` 目录。

### 2.3 首次登录

1. 打开浏览器访问前端地址：http://localhost:5173
2. 系统默认无需登录（后续版本将支持用户认证）
3. 进入仪表盘页面查看系统状态

## 3. 功能使用指南

### 3.1 仪表盘

#### 3.1.1 功能说明

仪表盘是系统的监控中心，实时显示：
- 系统性能指标（CPU、内存使用率）
- 通道状态统计
- 任务运行状态
- 最近告警记录

#### 3.1.2 操作步骤

1. **查看系统性能**
   - 仪表盘顶部显示4个统计卡片
   - CPU使用率：实时显示CPU占用百分比
   - 内存使用率：实时显示内存占用百分比
   - 活跃通道：显示在线通道数/总通道数
   - 运行任务：显示运行中任务数/总任务数

2. **查看通道状态**
   - 通道状态表格显示所有通道的实时信息
   - FPS：视频流帧率
   - 状态：在线/离线状态
   - 推理延迟：AI推理耗时（ms）

3. **查看告警记录**
   - 时间线显示最近5条告警
   - 点击告警卡片可查看详细信息
   - 告警包含：任务名称、告警类型、置信度、时间戳

#### 3.1.3 数据刷新

- 系统每5秒自动刷新数据
- 可手动刷新页面获取最新数据

### 3.2 通道管理

#### 3.2.1 功能说明

通道管理用于配置和管理视频流接入，支持多种协议的视频源。

#### 3.2.2 添加通道

**步骤1：点击"新增通道"按钮**

**步骤2：填写通道信息**
- **通道名称**：自定义名称，如"1号摄像头"
- **协议类型**：选择视频流协议
  - RTSP：实时流协议，常用于IP摄像头
  - RTMP：实时消息协议，常用于流媒体服务器
  - ONVIF：网络视频标准协议
  - USB：USB摄像头
  - 本地文件：本地视频文件路径
- **视频流地址**：根据协议类型填写
  - RTSP示例：`rtsp://admin:123456@192.168.1.100:554/ch1`
  - RTMP示例：`rtmp://192.168.1.100:1935/live/stream1`
  - USB示例：`0`（设备索引）
  - 文件示例：`D:/videos/test.mp4`
- **描述**：可选，添加备注信息

**步骤3：预览视频流（可选）**
- 点击"预览"按钮测试连接
- 预览成功后可确认保存

**步骤4：保存通道**
- 点击"确定"按钮保存
- 系统会自动检测通道状态

#### 3.2.3 编辑通道

1. 在通道列表中点击"编辑"按钮
2. 修改通道信息
3. 点击"确定"保存修改

#### 3.2.4 删除通道

1. 在通道列表中点击"删除"按钮
2. 确认删除操作
3. 注意：删除通道前需先停止使用该通道的任务

#### 3.2.5 批量检测

1. 点击"批量检测"按钮（待实现）
2. 系统会检测所有通道的连接状态
3. 检测结果会更新通道状态

#### 3.2.6 常见问题

**Q: RTSP连接失败怎么办？**
- 检查摄像头IP地址和端口是否正确
- 确认用户名和密码是否正确
- 检查网络连接是否正常
- 确认摄像头是否支持RTSP协议

**Q: USB摄像头无法识别？**
- 确认摄像头已正确连接
- 检查设备索引号（通常是0）
- 确认摄像头驱动已安装

### 3.3 模型中心

#### 3.3.1 功能说明

模型中心用于上传和管理AI模型文件，支持ONNX、OpenVINO、PaddlePaddle格式。

#### 3.3.2 上传模型

**步骤1：点击"上传模型"按钮**

**步骤2：选择模型文件**
- 支持拖拽上传或点击选择文件
- 支持格式：
  - ONNX：`.onnx` 文件
  - OpenVINO：`.xml` 和 `.bin` 文件（需同时上传）
  - PaddlePaddle：`.pdmodel` 文件

**步骤3：填写模型信息**
- **模型名称**：自定义名称，如"轮胎检测模型v1"
- **模型格式**：系统会自动识别，也可手动选择
- **描述**：可选，添加模型说明

**步骤4：上传**
- 点击"上传"按钮
- 等待上传完成（大文件可能需要较长时间）

#### 3.3.3 分析模型

**步骤1：上传模型后，点击"分析"按钮**

**步骤2：查看分析结果**
- **输入尺寸**：模型输入图像尺寸，如"640,640"
- **输入形状**：模型输入维度，如[1, 3, 640, 640]
- **标签列表**：模型输出类别标签
  - 如果模型目录下有 `_labels.json` 文件，会自动读取
  - 否则需要手动配置标签

**步骤3：确认标签**
- 检查标签是否正确
- 标签将用于任务配置中的目标选择

#### 3.3.4 模型标签配置

如果模型分析时没有自动识别标签，可以手动创建标签文件：

1. 在模型文件同目录下创建 `模型名_labels.json` 文件
2. 格式示例：
```json
["solid", "hollow"]
```
或
```json
{
  "labels": ["solid", "hollow"],
  "0": "solid",
  "1": "hollow"
}
```

#### 3.3.5 删除模型

1. 在模型卡片上点击"删除"按钮
2. 确认删除操作
3. 注意：删除模型前需先停止使用该模型的任务

#### 3.3.6 常见问题

**Q: 模型上传失败？**
- 检查文件格式是否支持
- 确认文件大小未超过限制
- 检查磁盘空间是否充足

**Q: 模型分析失败？**
- 确认模型文件完整未损坏
- 检查模型格式是否正确
- 查看后端日志获取详细错误信息

**Q: 如何获取模型标签？**
- 查看模型训练文档
- 联系模型提供方
- 使用模型分析工具查看模型结构

### 3.4 任务配置

#### 3.4.1 功能说明

任务配置是系统的核心功能，用于创建AI推理任务，包括资源选择、ROI配置和规则设置。

#### 3.4.2 创建任务（三步向导）

##### Step 1: 选择资源

**步骤1：填写任务名称**
- 输入任务名称，如"轮胎生产线2号位检测"

**步骤2：选择通道**
- 从下拉列表选择已配置的视频通道
- 确保通道状态为"在线"

**步骤3：选择模型**
- 从下拉列表选择已上传的AI模型
- 确保模型已分析完成

**步骤4：添加描述（可选）**
- 输入任务描述信息

**步骤5：点击"下一步"**

##### Step 2: 配置ROI

**步骤1：查看视频预览**
- 左侧显示选中通道的实时视频流
- 如果视频未显示，检查通道是否在线

**步骤2：选择绘制工具**
- **多边形**：点击画面上的点绘制多边形区域
- **矩形**：拖拽绘制矩形区域
- **绊线**：点击两点绘制虚拟线

**步骤3：绘制ROI区域**
- 多边形：在画面上依次点击多个点，形成闭合区域
- 矩形：按住鼠标左键拖拽绘制矩形
- 绊线：点击起点和终点绘制直线

**步骤4：管理ROI区域**
- ROI区域列表显示所有已绘制的区域
- 点击"删除"可移除某个ROI
- 点击"清除全部"可清除所有ROI

**步骤5：点击"下一步"**

**注意**：
- ROI区域用于限制检测范围，只有ROI内的检测结果才会触发规则
- 可以绘制多个ROI区域
- ROI配置是可选的，不配置则检测整个画面

##### Step 3: 设置规则

**步骤1：选择目标标签**
- 从下拉列表选择模型标签（如"hollow"）
- 只有匹配该标签的检测结果才会触发规则

**步骤2：设置置信度阈值**
- 使用滑块调整置信度阈值（0-1）
- 只有置信度大于等于阈值的检测结果才会触发
- 建议值：0.85-0.95

**步骤3：设置连续帧数**
- 输入连续帧数（如2）
- 表示连续N帧都检测到目标才触发规则
- 用于过滤误检，提高准确性

**步骤4：设置检测频率**
- 输入检测频率（如1）
- 表示每N帧检测一次
- 用于降低CPU负载，提高性能

**步骤5：配置输出动作（可选）**
- 选择输出类型：Modbus TCP、MQTT、Webhook
- 配置具体参数（见3.5节工业互联设置）

**步骤6：点击"保存"**

#### 3.4.3 启动任务

1. 在任务列表中点击"启动"按钮
2. 系统会：
   - 加载视频流
   - 加载AI模型
   - 启动推理线程
   - 开始执行检测
3. 任务状态变为"运行中"

#### 3.4.4 停止任务

1. 在任务列表中点击"停止"按钮
2. 系统会停止推理和视频流处理
3. 任务状态变为"已停止"

#### 3.4.5 编辑任务

1. 在任务列表中点击"编辑"按钮
2. 修改任务配置
3. 保存修改
4. 注意：运行中的任务需要先停止才能编辑

#### 3.4.6 克隆任务

1. 在任务列表中点击"克隆"按钮
2. 输入新任务名称
3. 系统会复制原任务的所有配置
4. 可以修改通道地址等参数快速创建相似任务

#### 3.4.7 删除任务

1. 在任务列表中点击"删除"按钮
2. 确认删除操作
3. 注意：运行中的任务需要先停止才能删除

#### 3.4.8 调试模式（待实现）

开启调试模式后：
- 实时显示AI识别框
- 显示识别结果和置信度
- 显示规则判定日志
- 显示触发动作日志

#### 3.4.9 常见问题

**Q: 任务启动失败？**
- 检查通道是否在线
- 检查模型是否已加载
- 查看后端日志获取错误信息

**Q: 检测结果不准确？**
- 调整置信度阈值
- 增加连续帧数过滤误检
- 检查ROI区域是否正确
- 确认模型标签配置正确

**Q: 任务运行卡顿？**
- 降低检测频率
- 检查CPU使用率
- 减少同时运行的任务数
- 优化模型（量化、剪枝）

### 3.5 工业互联设置

#### 3.5.1 功能说明

工业互联设置用于配置Modbus TCP、MQTT、Webhook等输出接口，实现AI检测结果与工业设备的联动。

#### 3.5.2 Modbus TCP配置

**步骤1：切换到"Modbus TCP"标签页**

**步骤2：配置PLC参数**
- **PLC IP地址**：PLC设备的IP地址，如`192.168.1.100`
- **端口**：Modbus TCP端口，默认502
- **从站ID**：PLC从站ID，默认1
- **超时时间**：连接超时时间（秒），默认5

**步骤3：测试连接**
- 点击"测试连接"按钮
- 系统会尝试连接PLC并读取寄存器
- 连接成功会显示提示信息

**步骤4：保存配置**
- 点击"保存配置"按钮
- 配置会保存到系统

**步骤5：在任务中配置输出**
- 创建任务时，在Step 3中配置输出动作
- 选择"Modbus TCP"
- 配置寄存器地址和数值
  - **寄存器地址**：要写入的寄存器地址，如0
  - **数值**：写入的值，如1（高电平）

#### 3.5.3 MQTT配置

**步骤1：切换到"MQTT"标签页**

**步骤2：配置MQTT Broker**
- **Broker地址**：MQTT服务器地址，如`192.168.1.200`
- **端口**：MQTT端口，默认1883
- **用户名**：MQTT用户名（可选）
- **密码**：MQTT密码（可选）
- **主题前缀**：消息主题前缀，如`/ai-edgehub`

**步骤3：测试连接**
- 点击"测试连接"按钮
- 系统会尝试连接MQTT Broker并发布测试消息

**步骤4：保存配置**

**步骤5：在任务中配置输出**
- 创建任务时配置MQTT输出
- **主题**：消息发布的主题，如`/factory/line1/alarm`
- **消息格式**：JSON格式，包含任务ID、检测结果、时间戳等

#### 3.5.4 Webhook配置

**步骤1：切换到"Webhook"标签页**

**步骤2：配置Webhook**
- **Webhook URL**：接收告警的HTTP接口地址
- **请求方法**：GET或POST
- **请求头**：JSON格式的自定义请求头（可选）

**步骤3：保存配置**

**步骤4：在任务中配置输出**
- 创建任务时配置Webhook输出
- 系统会在触发规则时发送HTTP请求到配置的URL

#### 3.5.5 模拟触发

**功能说明**：用于测试硬件联动是否正常，无需运行AI任务即可测试输出接口。

**操作步骤**：
1. 切换到"模拟触发"标签页
2. 选择输出类型（Modbus/MQTT/Webhook）
3. 点击"模拟触发"按钮
4. 系统会发送测试信号
5. 检查硬件设备是否响应

#### 3.5.6 常见问题

**Q: Modbus连接失败？**
- 检查PLC IP地址和端口是否正确
- 确认网络连接正常
- 检查PLC是否允许外部连接
- 确认从站ID是否正确

**Q: MQTT消息未收到？**
- 检查MQTT Broker地址和端口
- 确认主题名称正确
- 检查MQTT客户端是否订阅了正确主题
- 查看MQTT Broker日志

**Q: Webhook请求失败？**
- 检查URL是否正确
- 确认目标服务器可访问
- 检查请求方法是否正确
- 查看后端日志获取详细错误信息

## 4. 常见场景示例

### 4.1 场景一：轮胎红圈识别

**需求**：在轮胎生产线上，检测轮胎上的红圈是否为空心，如果是空心则触发分拣气缸动作。

**操作步骤**：

1. **创建通道**
   - 通道名称：轮胎生产线2号位
   - 协议：RTSP
   - 地址：`rtsp://admin:123456@192.168.1.100/ch1`
   - 预览确认连接正常

2. **上传模型**
   - 上传训练好的红圈检测模型（ONNX格式）
   - 分析模型，确认标签：`solid`（实心）、`hollow`（空心）

3. **创建任务**
   - Step 1：选择通道和模型
   - Step 2：绘制ROI区域（轮胎检测区域）
   - Step 3：设置规则
     - 目标标签：`hollow`
     - 置信度阈值：0.9
     - 连续帧数：2
   - Step 4：配置输出
     - 类型：Modbus TCP
     - 寄存器地址：0
     - 数值：1

4. **配置Modbus**
   - 在工业互联设置中配置PLC连接参数
   - 测试连接确认正常

5. **启动任务**
   - 启动任务开始检测
   - 实时查看检测结果和告警日志
   - 验证PLC联动是否正常

### 4.2 场景二：安全帽检测

**需求**：在工厂多个工位检测工人是否佩戴安全帽，未佩戴则发送告警。

**操作步骤**：

1. **批量创建通道**
   - 为每个工位创建RTSP通道
   - 批量检测通道状态

2. **上传模型**
   - 上传安全帽检测模型
   - 分析模型，确认标签：`person`、`helmet`、`no_helmet`

3. **创建第一个任务**
   - 配置通道、模型、规则
   - 目标标签：`no_helmet`
   - 置信度阈值：0.85
   - 输出：MQTT推送

4. **克隆任务**
   - 使用克隆功能快速创建其他工位的任务
   - 仅修改通道地址

5. **配置MQTT**
   - 配置MQTT Broker
   - 设置主题：`/factory/safety/helmet_alarm`

6. **启动所有任务**
   - 批量启动任务
   - 监控告警日志

### 4.3 场景三：产品缺陷检测

## 5. 故障排查

### 5.1 后端服务无法启动

**症状**：运行 `python run.py` 后报错或无法访问

**排查步骤**：

1. **检查Python版本**
   ```bash
   python --version
   ```
   确保版本 >= 3.8

2. **检查依赖安装**
   ```bash
   pip list
   ```
   确认所有依赖已正确安装

3. **检查端口占用**
   ```bash
   # Windows
   netstat -ano | findstr :8000
   
   # Linux
   lsof -i :8000
   ```
   如果端口被占用，修改 `.env` 中的PORT配置

4. **查看日志**
   - 检查 `logs/` 目录下的日志文件
   - 查看控制台错误信息

5. **检查数据库文件权限**
   - 确认有写入权限
   - 检查磁盘空间

### 5.2 视频流连接失败

**症状**：通道状态显示"离线"，无法预览视频

**排查步骤**：

1. **检查网络连接**
   - Ping摄像头IP地址
   - 确认网络可达

2. **检查RTSP地址格式**
   - 格式：`rtsp://用户名:密码@IP:端口/路径`
   - 确认用户名密码正确
   - 检查端口号（默认554）

3. **检查摄像头设置**
   - 确认摄像头RTSP功能已启用
   - 检查摄像头是否支持RTSP协议
   - 查看摄像头文档确认RTSP路径

4. **测试连接**
   - 使用VLC等播放器测试RTSP地址
   - 如果VLC能播放，说明地址正确

5. **检查防火墙**
   - 确认防火墙未阻止连接
   - 检查端口是否开放

### 5.3 模型加载失败

**症状**：任务启动时提示模型加载失败

**排查步骤**：

1. **检查模型文件**
   - 确认模型文件完整未损坏
   - 检查文件格式是否正确

2. **检查模型路径**
   - 确认模型文件在 `uploads/models/` 目录
   - 检查文件权限

3. **检查模型格式**
   - ONNX：确认是 `.onnx` 文件
   - OpenVINO：确认 `.xml` 和 `.bin` 文件都存在
   - 检查模型版本兼容性

4. **查看日志**
   - 查看后端日志获取详细错误信息
   - 常见错误：
     - 模型文件损坏
     - 模型格式不支持
     - 内存不足

### 5.4 推理性能问题

**症状**：推理延迟高，FPS低，CPU占用高

**排查步骤**：

1. **检查CPU使用率**
   - 查看仪表盘CPU使用率
   - 如果超过90%，考虑减少任务数

2. **调整检测频率**
   - 在任务配置中增加检测频率
   - 例如：从每帧检测改为每3帧检测一次

3. **优化模型**
   - 使用量化模型（INT8）
   - 使用更小的输入尺寸
   - 考虑模型剪枝

4. **减少并发任务**
   - 同时运行的任务数不要超过CPU核心数
   - 优先运行重要任务

5. **检查视频流分辨率**
   - 降低视频流分辨率
   - 使用硬件加速解码（如果支持）

### 5.5 告警未触发

**症状**：检测到目标但未触发告警或输出动作

**排查步骤**：

1. **检查规则配置**
   - 确认目标标签正确
   - 检查置信度阈值是否过高
   - 确认连续帧数设置合理

2. **检查ROI配置**
   - 确认ROI区域包含检测目标
   - 检查ROI坐标是否正确

3. **检查输出配置**
   - 确认输出类型配置正确
   - 检查Modbus/MQTT/Webhook连接是否正常
   - 使用"模拟触发"测试输出接口

4. **查看日志**
   - 检查任务执行日志
   - 查看是否有错误信息

5. **调试模式**
   - 开启调试模式查看实时检测结果
   - 确认检测框是否正确显示

### 5.6 WebSocket连接失败

**症状**：前端无法接收实时数据，视频预览不显示

**排查步骤**：

1. **检查WebSocket地址**
   - 确认地址格式正确：`ws://localhost:8000/ws`
   - 检查端口号是否正确

2. **检查CORS配置**
   - 确认 `.env` 中CORS_ORIGINS包含前端地址
   - 重启后端服务使配置生效

3. **检查网络连接**
   - 确认前后端网络连通
   - 检查防火墙设置

4. **查看浏览器控制台**
   - 打开浏览器开发者工具
   - 查看Console和Network标签页的错误信息

## 6. 常见问题

### 6.1 系统相关

**Q: 系统支持哪些操作系统？**
A: 支持Windows、Linux、MacOS。推荐使用Linux服务器部署。

**Q: 需要GPU吗？**
A: 不需要。系统针对Intel CPU优化，使用OpenVINO加速，无需GPU。

**Q: 支持多少路视频流？**
A: 取决于CPU性能。推荐配置（i7-12700）可支持8-16路视频流。

**Q: 如何备份数据？**
A: 备份 `ai_edgehub.db` 数据库文件和 `uploads/` 目录。

### 6.2 视频流相关

**Q: 支持哪些视频流协议？**
A: 支持RTSP、RTMP、ONVIF、USB摄像头、本地视频文件。

**Q: 如何获取RTSP地址？**
A: 查看摄像头说明书或登录摄像头Web界面查看RTSP设置。

**Q: USB摄像头设备索引是什么？**
A: 通常是0。如果有多个USB设备，依次为0、1、2...

**Q: 视频流断线会自动重连吗？**
A: 是的。系统会自动检测断线并尝试重连。

### 6.3 模型相关

**Q: 支持哪些模型格式？**
A: 支持ONNX、OpenVINO（.xml+.bin）、PaddlePaddle（.pdmodel）。

**Q: 如何转换模型格式？**
A: 
- 转ONNX：使用ONNX官方工具或PyTorch/TensorFlow导出
- 转OpenVINO：使用OpenVINO Model Optimizer
- 转PaddlePaddle：使用PaddlePaddle转换工具

**Q: 模型文件大小有限制吗？**
A: 建议单个模型文件不超过500MB。大模型会影响加载速度。

**Q: 如何获取模型标签？**
A: 查看模型训练文档，或使用模型分析工具查看模型结构。

### 6.4 任务相关

**Q: 可以同时运行多少个任务？**
A: 取决于CPU性能。建议不超过CPU核心数。

**Q: 任务可以暂停吗？**
A: 当前版本不支持暂停，可以停止后重新启动。

**Q: 如何查看任务执行日志？**
A: 查看后端日志文件 `logs/app_*.log`。

**Q: 任务配置可以导出吗？**
A: 当前版本不支持，后续版本会添加导入导出功能。

### 6.5 工业联动相关

**Q: Modbus TCP支持哪些功能码？**
A: 当前支持读写保持寄存器（03/06功能码）。

**Q: MQTT支持TLS加密吗？**
A: 当前版本不支持，后续版本会添加。

**Q: Webhook支持哪些HTTP方法？**
A: 支持GET和POST方法。

**Q: 如何测试输出接口？**
A: 使用"模拟触发"功能，无需运行AI任务即可测试。
